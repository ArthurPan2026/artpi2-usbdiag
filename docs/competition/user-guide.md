# 使用指南

## 首次配置 WiFi

首次启动时没有预设网络。打开 LCD 的“设置 → WiFi → 扫描”，选择目标 2.4 GHz 网络并输入密码；开放网络无需密码。保存网络开启时，只有关联并取得 IPv4 后才会保存凭据。

连接后从 LCD WiFi 页面或路由器 DHCP 客户端列表查看板端 IP，并让浏览器设备接入同一局域网。

## 开始一次真实观测

1. 给 ART-Pi2 上电，确认板端 USB Host 口连接一个真实 HID 设备。
2. 从 LCD WiFi 页面或路由器 DHCP 客户端列表记录板端 IP；开发电脑接入同一局域网。
3. 浏览器打开 `http://<板端IP>/`。默认进入“HID 接入”；Web 只展示开发板发布的当前设备清单和证据快照，不支持离线文件导入。
4. 查看接口/端点拓扑、Host 类驱动绑定状态和描述符完整性。若清单正在变化或捕获不完整，页面会标出状态；驱动绑定不代表已验证 HID 输入报告收发。
5. 切到“教学导览”，查看设备 VID:PID、采集完整性、会话结论与八阶段时间线。时间线是 Host 软件观察顺序；教学核验任务按当前证据作答，快照代号变化后答案会重置。
6. 切到“研发核验”，选择规则、事件或描述符字段，检查请求参数、期望/实测、规范条款和原始字节。
7. 选择“生成并预览 PDF”后，浏览器会在新标签页打开报告；可使用浏览器 PDF 工具栏下载或打印。“导出完整证据”会按当前代号取齐并验证摘要与事件 CRC。

## 隐私与证据边界

- 教学导览默认遮盖设备序列号；研发视图可按需手动显示。
- PDF 核验报告默认遮盖序列号；自包含原始证据导出保留板端原值。
- `/api/history` 只保存历史摘要，不是完整原始证据。
- `PASS` 只表示规则在当前捕获数据上通过；证据完整性不完整时不会给整体通过结论。
- 描述符规则违规不是硬件根因诊断。Host 超时也不能单独证明外设损坏。

## 无法连接时

- 确认 LCD WiFi 页面显示已连接且板端 IP 有效，再检查客户端和开发板是否在同一子网。
- 运行 `test-artpi2.ps1 -BoardUri http://<board-ip>` 核对构建身份、联网、HID 枚举和证据完整性。
- 若出现 409，页面会读取新代号；416 表示所请求范围无效；503 为板端暂忙且有界重试。
- 页面停留在“上次已校验快照”时，不要将其误认为实时更新。
