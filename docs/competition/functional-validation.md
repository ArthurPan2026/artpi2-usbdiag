# 功能验证清单（Release）

本清单列出 Release 版本的核心功能检查。执行时记录实际结果，不把未执行的检查写成已通过。

## 复现准备

先按[构建与运行指南](reproducibility.md)构建并刷入 `Release` Boot 和 Appli XIP。连接真实 HID，让电脑与板端位于同一局域网。保存本次 `/api/build` 的 `source_fingerprint`，确认 `build_type` 为 `Release`。

## 板端与 UI

- 上电后 LCD 显示首页，不停留在初始化占位状态。
- 从 LCD WiFi 页面或路由器 DHCP 客户端列表确认板端 IP；浏览器可打开 `http://<board-ip>/`，`/api/wifi/status` 报告已联网。
- 检查首页、描述符、诊断、设置四个页面可以打开和返回，文字完整、布局无明显裁切。
- 教学视图可以查看设备身份和枚举阶段，并完成四项证据核验任务。
- 研发视图中选择规则、事件和描述符节点时，关联详情与原始字节能同步定位。

## USB 枚举与证据

- 在网页确认连接的 HID 已枚举，并查看 `/api/usb/interfaces` 中的 HID 接口数量。参考设备 Xiaomi Mi USB Receiver（VID:PID `2717:5091`）应呈现三个 HID 接口；换用其他 HID 时以其真实接口数为准。
- 板端 Web 页面显示当前捕获会话和规则结果。参考设备的已记录会话包含 17 个事件、12 条通过规则、0 个丢失事件；数值应与本次实际设备和捕获一致。
- 在浏览器导出完整证据 JSON；确认快照代号一致，事件、规则结果和摘要数据均存在。
- 生成并预览 PDF 核验报告；检查浏览器 PDF 工具栏可用，报告中的会话代号、CRC、规则和事件计数与当前快照一致，序列号已遮盖；可从工具栏下载或打印。
- 在浏览器打开 `/api/build` 和 `/api/evidence`，确认构建身份为 Release，证据快照包含代号、版本、规则结果和完整性字段。
- 对照页面和 `/api/evidence` 的快照代号；查看摘要 CRC 与各原始事件 CRC 字段是否随导出数据保留。
- 可运行 `test-artpi2.ps1 -BoardUri http://<board-ip>` 做短 Web 冒烟，核对构建身份、联网、HID 枚举和证据 CRC。

## 故障恢复与日志读取

- 将 Boot 与 Appli Release 一起刷入后，确认正常空闲、无 HID、WiFi 离线和 Web/PDF 空闲时不会触发复位。
- 执行一次正常软件重启或冷启动后，确认不会增加异常日志条目，连续 IWDG 复位计数回到零。
- 在开发验证构建中触发受控看门狗复位；重新启动后读取外部 Flash 日志，检查复位原因、构建指纹、最近进度/事件、CRC 与记录序号。
- 连续追加超过 64 条日志，检查事务暂存扇区先提交新记录，再回收最旧记录；在写入或回收中断后，检查 Boot 能跳过无效扇区并保留最近 64 条有效日志。
- 如果连续 3 次 IWDG 复位进入 Boot 恢复状态，通过 UART4 发送 `RECOVER` 并回车后，确认 MCU 重启且复位计数清零。
- 故障记录表示最近一次成功采样；硬件复位后无法保证捕获 CPU 卡死瞬间的完整内存。

## 报告结果时的边界

- 只报告本次 Release 镜像和本次 HID 捕获的结果。不同 HID 的事件顺序、接口数和规则结果可能不同。
- Web 短冒烟不替代 LCD 目视、页面触摸、物理断电冷启动或真实 USB 拔插检查；需要核验这些交互时应手动操作并记录。
